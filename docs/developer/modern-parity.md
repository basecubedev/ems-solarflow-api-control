# Classic and Modern: what each front end can do

Owner, 2026-10-21: the Modern Admin console listed the release versions but
could not install one, and nothing caught it. Every function the Classic
front ends offer is therefore listed here with what Modern does about it, and
a test keeps the list honest. This page is the work list for a Modern that
works on its own.

## How the list is kept

- **Every API path Classic calls is either called by Modern or named below as
  Classic-only.** `tests/test_modern_parity.py` reads the paths out of
  `admin/static/admin.js`, `dashboard/static/app.js` and
  `dashboard/static/index.html`, looks for each in the Modern sources
  (`frontend/admin-modern/src`, `frontend/dashboard-modern/src`,
  `frontend/shared`), and compares what it cannot find with the registry at the
  end of this page. A new Classic function on a path Modern does not use fails
  the test until it is built in Modern or added to the registry; a path Modern
  starts to use fails it until it leaves the registry.
- **The function tables** came from an inventory of both Classic front ends
  (2026-10-21/22): every control and request, matched against the Modern code
  and then checked a second time by a reviewer who tried to refute each verdict.
  "Checked twice" counts the verdicts that went through that second check; the
  rest rest on the first reading. Update a row in the change that alters it.
- A path being called is not proof of a function being usable: the release list
  called the right catalogue and still could not start an upgrade. The tables
  below therefore judge controls, not requests; "shows only" marks data Modern
  displays without the action Classic offers on it.

"Native" means Modern does it itself. "Hands off" means Modern names it and
opens Classic at the right page. "Shows only" means Modern shows the data but
offers no action on it. "Missing" means Modern neither does it nor hands it off.
"By design" means it is deliberately not part of Modern.
