## Open defects that keep this release from being physical-ready

1. `backup_ssh_dir_unreadable` — the confined backup account can never complete
   an SFTP session. `appliance/sshkeys.py` creates the account's `.ssh` at mode
   0700 owned by root, and sshd reads `authorized_keys` as the account, so the
   directory cannot be traversed and the key is never read. The key itself is
   correct: the fingerprint in `authorized_keys` is the one the appliance issued
   through its own authenticated API.
2. `runtime_seed_unaddressable` — the offline Docker seed is written on every
   slot switch and can never be used. `docker save` writes no repository digest
   into the archive, so after `docker load` the image is present under no name
   the runtime record can ask for, and reconstruction always falls back to the
   registry the seed exists to avoid. It fails safe — the trial rolls back — but
   the no-WAN guarantee is not real.

Both are refusals, not silent successes, and both are why `physical_ready` is
false. The release itself — source, builds, images, updates, signature — is
internally consistent and re-verifiable from this directory.
